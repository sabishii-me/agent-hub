## What was reviewed

All 32 test files under `tests/` (the whole suite is this session's work; there was no
pre-existing Python suite). Each was read and its assertions classified:

- **FAKE** — the assertion accepts the very failure the test exists to catch (`x is not None`,
  a loose `in (...)` that includes the wrong outcome, `or warning`).
- **REAL** — the assertion is the SPECIFIC fact a source (contract/ARCHITECTURE/issue) requires.

## Per-file provenance (now in every file)

Every test now carries a header:

```
# FACT:    the fact it proves
# SOURCE:  contract/v1.json | ARCHITECTURE sec N | ADR | docs/issues/<id>
# EXPOSES: the wrong behaviour it would catch
```

A header with no source is not allowed: a test must cite where its fact comes from.

## Rule for future tests (do not break)

- An assertion must name a fact and cite a SOURCE. No `is not None`, no loose `in (...)`, no
  `or warning` where the source pins one value.
- When a test goes red after being made specific, the fix is the PRODUCT. Never relax the
  assertion to pass.
